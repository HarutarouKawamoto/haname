# 席予約 API レビュー結果

## 概要

席予約 API（`POST /reservations`）の実装を確認しました。入力の確認・空きの確認・保存が関数に分かれていて、読みやすい構成です。ただし、同時に予約が来たときの扱いと、時間帯の判定に直すべき点があります。

## 指摘

### 1. 同時に来た予約が、同じ席に入ってしまう

空きの確認と保存が、別々の問い合わせになっています。2 人がほぼ同時に同じ席を予約すると、どちらの確認も通り、両方が保存されます。保存の時点で、データベースに重なりを拒ませてください。PostgreSQL なら排他制約で、同じ席の時間帯の重なりを禁止できます。

### 2. 時間帯の重なりを、開始時刻だけで判定している

`isOverlapping` は、開始時刻が同じかどうかしか見ていません。10:00〜11:30 の予約があるとき、10:30〜12:00 の予約を通してしまいます。2 つの区間の両端を比べてください。

```ts
export function isOverlapping(a: Slot, b: Slot): boolean {
  return a.from < b.to && b.from < a.to;
}
```

### 3. 取り消した予約も、空きの確認に含めている

`status` が `cancelled` の予約も「埋まっている」と数えています。取り消しのあった枠が、いつまでも予約できません。

## 良い点

- 結果を判別可能なユニオン型で返していて、409 と 422 の違いが呼び出し側に伝わる。
- 営業時間の境目（8:00 ちょうど、18:00 ちょうど）のテストがある。
