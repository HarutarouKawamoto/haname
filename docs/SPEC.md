# HanaME（花見）仕様（MVP）

## コンセプト

| 軸 | 意味 |
|---|---|
| 使いやすい | 画面操作がしやすい。AIサブスク利用者の開発フローにそのまま入れる |
| 利用しやすい | 導入・起動の手間がない |
| 効率的 | 機能を絞る。大量の.mdを要約せずに素早く読み解ける |

最大の目的は「読みやすく、壁打ちしやすく」。

## 全体方針

- AIのAPIは使わない。ファイルを直接操作できるAIツール（Claude Code / Codex CLI / Cursor 等）との橋渡しに徹する。
- ボタンに文字を使わない。アイコンは Lucide。ツールチップは最終手段。

## 問題① 追記コメント（壁打ち）

### 書き込み先

- 元の.mdに直接書き込む。
- 最初に書き込む直前に、元ファイルを `.haname/backup/` へ一度だけ保存する（保険）。

### 質問の付け方

- マウスを乗せると文単位でハイライト。クリックで質問欄が開き、対象の文が引用される。
- 文字をなぞってからクリックすると、`「〇〇」とは？` の下書きが入る。

### 書式

```markdown
## 見出し

> [!ANSWER] Q1
> （AIが記入）

本文の段落。対象の文。

> [!QUESTION] Q1 対象:「対象の文。」
> 質問の内容
```

- 回答は、対象の文から見て一番近い見出しの直下に積み重ねる。見出しがなければファイル先頭。
- 質問は、対象ブロック（段落・リスト・表・コード）の直後。
- 回答への追加の質問は、元の回答の下にスレッドとしてつなげる（`Q1-1`、`Q1-1-1`）。

### AIへの渡し方

- 指示文をクリップボードにコピーするボタン。フォルダ内の「未回答の質問があるファイル」すべてを1つの指示文にまとめる（一括で渡す）。
- ブラウザのチャット向けに、それらのファイルの中身ごとコピーするボタン。
- バッジはフォルダ全体の未回答の数。コピーする内容と同じ数になるようにする。
  - 開いているファイルは、表示中の内容と一覧のうち更新時刻が新しいほうで数える（質問を書きかけの間・編集モードの間は表示を読み直さないため）。
  - ファイル変更の通知は取りこぼすことがある（監視の取りこぼし、スリープなどでの接続切れ、つながるまでの間の変更）。通知に加えて、つながったとき・ウィンドウに戻ったとき・10 秒ごと（画面が見えている間）・コピーしたあとにも確かめ直す。変わっていなければ描き直さない。
  - 一覧と表示の読み込みは、古い結果が後から届いても新しい結果を上書きしない。
  - サーバーは未回答の数をファイルの更新時刻と大きさごとに覚える。書き込みの途中は読まない（読む前後で変わっていないことを確かめる）。書き込まれて 2 秒以内のファイルは覚えずに毎回読む（更新時刻が変わらないまま中身が変わることがあるため）。一覧を作る間に消えたファイルは飛ばす。
- `haname init` で AI 側にも準備する。`CLAUDE.md` / `AGENTS.md` に Q&A のルールを書き足し（印で囲んだ部分だけを更新）、`.claude/skills/haname-answer/SKILL.md` に回答の手順をまとめたスキルを置く。スキルがあれば、AI は自分で未回答の質問を探して回答する。
- 回答は10行ほどまで。理解に10行を超える説明が要るときは要約せず、回答欄には結論とその旨を書き、質問ごとの新しい .md（元のファイルと同じフォルダの `<元のファイル名>-<番号>.md`）を提案する。了承されたら作成し、回答欄からリンクする（スキルで決める。HanaME 本体の動作は変えない）。

### 表示

- ファイル変更を検知して自動で再読み込み。
- コードブロックは、言語名があれば highlight.js で色分けする。配色は VS Code の Light+ / Dark+ に合わせ、テーマに連動する。言語名がないブロックは色分けしない（自動判定は誤りやすいため）。
- ` ```mermaid ` は Mermaid の図にする。Mermaid（約 3.5MB）は図のあるページでだけ読み込む。配色はテーマに連動（昼は neutral、夜は dark）し、切り替えると描き直す。右上のボタン（アイコンのみ）で図とコードを切り替える。書き間違いのときは、コードと「図の書き方に誤りがあります」を出す。
  - 図の部品（箱・矢印のラベル・クラスタ・文字）にマウスを乗せると桜色に光り、クリックするとその部品への質問欄が開く。対象は、コードの中でその部品を定義している部分（`B{在庫はある?}`、`-- ない -->`、`participant S as サーバー` の行など）。何もないところをクリックしたときは図全体への質問で、対象はコードの 1 行目。質問はコードブロックの直後に入る（コードの行への質問と同じ）。AI の回答の中の図なら、その回答への追加の質問になる。
  - 質問済みの部品は桜色の影、図全体への質問は点線の枠で示す。対象が図の上で見つからない質問（設定の行など）しかないときは、コードの表示で始める。
- 表・図・画像には、右上に拡大のボタン（アイコンのみ）を付ける。拡大表示は画面いっぱいの重ね表示で、ホイールで拡大・縮小（マウスの位置を中心に）、ドラッグで移動、ボタンで縮小・画面に合わせる・拡大・閉じる。Esc・背景のクリックで閉じる。キーボードは + / - / 0。開いている間は ← → のページ送りをしない。
- `<details>` / `<summary>` の折りたたみを表示する。目次・Q&A の番号から閉じた折りたたみの中へ移動するときは開く。
  - 「HTML のかたまり」として扱う行は、折りたたみのタグだけの行と HTML のコメントに限る。`<div>` などで始まる行は普通の段落として扱い、タグは文字として出し、続く Markdown は描画する（markdown-it の標準では次の空行まで丸ごと HTML になり、Markdown が描画されないため）。
  - 折りたたみのタグの行は 1 行ずつ区切る。`<summary>` の直後に空行がなくても、続く行は Markdown として描画する（GitHub では空行が必要なので、両方で読む .md では空行を入れる）。
- コードブロックは1行を1文として扱い、行をクリックすると質問欄が開く。質問はコードブロックの直後に入る。
- 回答 ⇄ 質問 をクリックでジャンプ。スレッドは折りたたみ可能。
- 片付けは「隠す（表示だけ）」と「削除」の2つ。
- 削除は消しゴムボタンを1回押すと削除モード。そのままもう1回押すと全部削除。削除モード中に Q&A の枠をクリックして選ぶと、2回目でその組（質問と回答）とスレッドだけ削除。Esc で取り消し。

### 保留

- 回答だけ残す（`[!NOTE]` 化）
- バックアップから戻す画面

## 元に戻す / やり直す

- Ctrl+Z で、開いているファイルへの HanaME の書き込み（質問の追加・Q&A の削除・編集の保存）を1つずつ戻す。Ctrl+Shift+Z / Ctrl+Y でやり直す。
- AI などが後から書き換えたファイルは戻さない（後から書き込まれた内容を消さないため）。
- 履歴はファイルごとに最大50件。ビューアを終了すると消える。入力欄の中では、ブラウザ標準の文字単位の元に戻すが働く。

## 編集モード

- 鉛筆ボタンで編集モード。本文だけを編集し、Q&Aは表示しない。
- 保存（ボタン / Ctrl+S）時、本文の変更箇所を照らし合わせて Q&A を元の位置関係で戻す。対象の行が書き換えられた場合は、書き換え後の範囲の直後に置く。
- 編集中に AI が Q&A だけを書き換えても、そのまま保存できる。本文そのものが外部で変わっていた場合は保存せず、編集内容を残す。
- 未保存の変更があるときは、他のファイルへの移動と「やめる」を止める（やめるは2回押しで確定）。

## 配色

- 白・グレーの無彩色を土台に、アクセントだけ桜色（#E9A3B6）。ホバー・選択・質問の枠・未読の点などに使う。
- ライトとダーク。初期値は OS の設定、ボタンで切り替えて記憶。
- ロゴは public/brand/。ダークでは文字を明るくした版に差し替える。

## 問題② 大量の.md

- 右にツリー、クリックしたファイルを1つ表示。複数同時表示・タブは採用しない。
- 前後ボタンと ← → キーでページめくり。順番はツリーの並び（名前順）。フォルダをまたいで続く。
- ファイル操作は「移動」だけ（既存フォルダへ、複数選択してドラッグ）。リンク切れが起きる場合はアイコン＋件数で警告。
- 起動は `npx haname`。そのフォルダ以下の.mdを表示。`node_modules`・`.git`・`.haname`・`.gitignore` の対象は除外。
- AI ツールの設定・指示のファイル（`.claude` などのフォルダ、`CLAUDE.md`・`AGENTS.md`・`GEMINI.md` など、`.github` の Copilot 用ファイル）は初期設定で除外。`--ai-files`（`createServer(root, { aiFiles: true })`）で表示する。一覧は `lib/server.js` の `isAiPath`。
- 目印: 未読 = ピンクの ●、開いた後に更新あり = 黄緑の ○。

## セキュリティ

- Node.js は Node2Shell（CVE-2026-111497）の修正版（22.23.4 / 24.22.1 / 26.12.1）以降のみ。古い版では起動を拒否する（`package.json` の engines も同じ範囲）。
- サーバーは 127.0.0.1 だけで待ち受ける。Host ヘッダーが `localhost` / `127.0.0.1` 以外の要求は拒否（DNS リバインディング対策）。
- 書き込み系の要求は、Origin が自分自身のときだけ受け付ける（CSRF 対策）。CLI からの `/api/open` は `.haname/server.json` のトークンで確認する。
- 読み書きできるのは、起動したフォルダの中の、ツリーに出る .md（と画像）だけ。`../` やシンボリックリンク・ジャンクションでフォルダの外を指すもの、除外フォルダ（`.git` など）と `.gitignore` の対象は拒否する。
- Markdown は生の HTML を描画しない（文字として表示。HTML のコメントは表示しない）。例外は `<details>` / `<summary>` だけで、タグはそのまま通さず組み立て直す（属性は details の `open` だけ残す）。
- Mermaid は `securityLevel: 'strict'`（図の中の HTML・スクリプト・クリック動作を無効）で描き、さらに図の中のリンク先を外す。Mermaid は npm の依存にせず、ブラウザ用の 1 ファイルを `public/vendor/` に取り込む（`scripts/update-mermaid.mjs`。同梱部品のライセンス表示は `mermaid.LICENSES.txt`）。
- `javascript:` などのリンクはリンクにしない。画面には CSP（自分のサーバーのスクリプトだけを実行）と、クリックジャッキング・MIME 推測を防ぐヘッダーを付ける。
- ブラウザは `cmd.exe` を通さずに開き、開く URL は自分のサーバーのものに限る。
- AI 向けの説明では `npx haname` を勧めない。npm に未公開のため、同じ名前の別パッケージを実行させてしまうおそれがある。
- 残るリスク: .md の中身はそのまま AI への指示文に入るため、.md に AI への指示が埋め込まれていると AI がそれに従う可能性がある（プロンプトインジェクション）。外部の画像を載せた .md を開くと、その画像のサーバーに接続する。
